# fixloop server

The backend for the maintenance coordination product in [`../docs`](../docs). `fixloop` is a working codename. The scope comes from [`docs/prd.md`](../docs/prd.md).

## Quick start

```bash
docker compose up -d          # Postgres 17 on :5433, MinIO on :9100 (console :9101)
cp .env.example .env
npm install
npm run db:migrate
npm run dev                   # API on :4000
npm run worker                # outbox + reminders + cleanup (separate process)
npm test                      # unit + integration tests against real Postgres and MinIO
npm run superadmin -- list    # manage Fixloop staff accounts (add | reset | disable | enable | list | code)
```

## Stack and why

| Layer | Choice | Why |
|---|---|---|
| Runtime | Node 22+ / TypeScript (strict, `noUncheckedIndexedAccess`) | One language with the web app in `../web` |
| HTTP | Fastify 5 + Zod (`fastify-type-provider-zod`) | Fastest mainstream Node framework. Every input is schema-validated, and handler types come from the schemas |
| DB | PostgreSQL 17 + Drizzle ORM + postgres.js | Relational data with transactions and row-level security. Drizzle is SQL-shaped, so nothing hides queries |
| Jobs | Postgres outbox + reminder tables, `FOR UPDATE SKIP LOCKED` | No Redis or queue to run. Messages are written in the same transaction as the state change. Scales out by adding workers |
| Files | S3-compatible (MinIO locally, S3/R2 in prod), presigned POST | File bytes never pass through the API. S3 enforces key, type and size |
| Auth | Opaque session tokens (SHA-256 stored), argon2id passwords | Revocable ("sign out everywhere"), no JWT pitfalls |
| Email/SMS | Postmark / Twilio over `fetch`, with a log provider in dev | No SDK weight. Both are behind one small interface |

## Layout

```
src/
  app.ts                 buildApp(deps): plugins + route modules (deps injected, so tests reuse it)
  server.ts / worker.ts  the two processes
  cli/superadmin.ts      create and manage superadmins (there is no web sign-up for them)
  config/env.ts          env validated by Zod at boot; fails fast
  db/
    schema/              tables by domain: identity, portfolio, maintenance, comms, platform (superadmins, security log)
    migrations/          generated by drizzle-kit; hand-written SQL appended where needed (RLS, grants, functions)
    client.ts            pool + withOrg() (RLS transaction)
  plugins/               errors, auth (session → req.auth), security (helmet, CORS, rate limit, CSRF)
  shared/                cross-module domain services: timeline, outbox, reminders, counters, actor, security-log
  lib/                   errors, crypto, totp, validation, csv
  modules/<domain>/      routes + service per domain
    work-orders/         state-machine.ts (pure), policy.ts (SLAs/reminder plan, pure), core.ts (move(), inputs,
                         messaging helpers), work-orders.service.ts + quotes.service.ts (commands), routes
    platform/            superadmin console API (/platform): its own session, firms, suspensions, security log
    requests/ links/ public/ vendors/ portfolio/ org/ files/ dashboard/ reports/ auth/ notifications/
  jobs/                  dispatch (outbox), reminders, cleanup
test/unit, test/integration
```

**Rules that keep it maintainable:**
- Every work order change goes through `move()` in `work-orders/core.ts`. That one function validates the transition with the pure state machine, writes the status and timeline event, and replans reminders, all in the caller's transaction. Status is never updated directly.
- Routes stay thin: parse, call a service with a `Ctx` (tx, org, actor, now), return.
- Pure logic (state machine, reminder planning, compliance, CSV) has no I/O and is unit-tested exhaustively.

## Security model

- **Tenant isolation, two layers.**
  1. Every firm-scoped table has a Postgres RLS policy on `app.org_id`. The API connects as `app_user`, which owns no tables and can't bypass RLS. With the setting unset, it sees zero rows.
  2. Composite foreign keys `(org_id, id)` stop a row in one firm from referencing another firm's data.

  The identity tables (`organizations`, `users`, `sessions`, `access_links`) are read before a firm context exists, so code scopes them instead. The platform tables (`platform_admins`, `platform_sessions`, `security_events`) belong to Fixloop staff, not to a firm. A test fails if any new table with `org_id` lacks RLS (`security_events` is the one listed exception).
  The superadmin console reaches firm tables only through `platform_org_stats(ids)`, a `SECURITY DEFINER` function that returns counts, never rows.
- **No-login links.** These are 256-bit random tokens. Only their SHA-256 is stored, and each is limited to one purpose and one object, with an expiry. They're minted at send time, so raw tokens never rest in the outbox. Reassigning a vendor revokes their links. Unknown and malformed tokens get the same 404. Link views are built field by field, so internal notes and other parties' data can't leak, and a vendor sees tenant contact details only after accepting the job.
- **Sessions:**
  - httpOnly cookies, `SameSite=Lax`, `__Host-` prefixed and Secure in production
  - a 30-day lifetime
  - last-seen time written at most once every 5 minutes
  - a session only works while the user is active, their email is confirmed (`requireAuth`; `/auth/me`, logout and resend are the only exceptions) and their firm isn't suspended
- **CSRF.** Cookie-authenticated writes must carry our own `Origin`, and a foreign Origin is rejected even when signed out.
- **Passwords:**
  - argon2id (OWASP parameters)
  - Have I Been Pwned breach check using k-anonymity
  - lockout after 10 failures, with an atomic counter
  - constant-time behaviour for unknown emails
  - resets revoke every session
- **Abuse limits:**
  - global and per-route rate limits
  - 1 MB JSON body cap
  - 15-second database statement timeout
  - stricter per-IP limits on public intake and links
- **Uploads.** The server chooses the key, inside the firm's prefix. The presigned policy pins the exact content type and size range, and completion re-checks the stored object. Non-images download with `Content-Disposition: attachment`. Abandoned uploads are deleted after 24 hours.
- **Outputs:**
  - emails are plain text, so user strings never render as HTML
  - CSV exports neutralise formula injection
  - logs redact cookies, auth headers and link tokens
- **Email confirmation.** Sign-up sends a 48-hour, single-use `email_verify` link; the page confirms on a button press, so mail scanners opening the link can't. Invites and password resets confirm the address too.
- **Suspension.** A superadmin can suspend a firm: its sessions stop on the next request, sign-in returns `org_suspended`, links return 410, the public request form 404s and the worker skips its messages. Nothing is deleted.
- **Superadmins.** A separate table and cookie (`SameSite=Strict`), password plus TOTP (RFC 6238, a code is accepted once), lockout after 5 failures, 8-hour sessions with a 30-minute idle timeout. Created only from the server CLI.
- **Audit.**
  - `events` (each firm's timeline) is append-only for the API role (no UPDATE or DELETE grant).
  - `security_events` records sign-ins and failures with a reason, lockouts, password and email changes, team changes and every superadmin action. The API can only INSERT and SELECT it; the worker prunes entries after 400 days.
- **Startup guards.**
  - In production, the API refuses to start if its database role could bypass row-level security (superuser, `BYPASSRLS`, or table owner), or if `DATABASE_URL` uses the owner role.
  - It also refuses `EMAIL_PROVIDER=log`, a non-https `APP_URL` and `TRUST_PROXY=0` in production.
  - `TRUST_PROXY` is an explicit hop count, so `X-Forwarded-For` can't be spoofed to dodge rate limits. Behind nginx it must be at least 1, or every user shares the proxy's IP and one person's typos lock everyone out of sign-in.
- **No state changes on GET.** Exporting expenses as "billed" is a POST (`/reports/expenses/export`); `GET /reports/expenses.csv` is read-only.

## Performance notes

- Lists use keyset pagination, ordered by `(created_at, id)` with indexes, never OFFSET.
- Text search inside a firm is `ILIKE '%…%'` over that firm's rows only. Under RLS, Postgres won't use a non-LEAKPROOF operator such as ILIKE as an index condition, so trigram indexes don't help there: a search that matches nothing costs about 20–40 ms for a 300-door firm. The security log has no RLS and uses trigram indexes on email and IP; every superadmin listing stays under 50 ms at 1M log entries.
- The dashboard's stat tiles come from one aggregate query. Detail pages load related data with parallel queries inside one transaction. No N+1 queries.
- Work order commands lock only the work order row (`FOR UPDATE OF work_orders`). Concurrent actions on one job serialise and get a clean 409, while other jobs never wait.
- Reference numbers (`MR-2026-001`) come from a single-row upsert. They're concurrency-safe and gapless per firm and year, and tested with 15 parallel inserts.
- Vendor report milestones (`assigned_at`, `accepted_at`, `completed_at`) are stored on the work order, so reports don't mine the event log.
- The pool uses `prepare: false`, so it works behind transaction-mode poolers (PgBouncer, Supavisor).

## Operations

- **Superadmins.** Create the first one after the first deploy: `node dist/cli/superadmin.js add you@company.com "Your Name"` with the API's `DATABASE_URL`. It prints a password and an authenticator setup key once. The console is at `/ops`.
- **Production run.** `npm run build`, then `npm run start:migrate` (owner role) once per release, `npm start` (API, `app_user`) and `npm run start:worker`. Build the SPA with `cd ../web && npm run build` and serve it with [`../deploy/nginx.conf`](../deploy/nginx.conf): same origin, `/api` proxied to the API, CSP and security headers, immutable `/assets`. Set `NODE_ENV=production`, an `https://` `APP_URL`, `EMAIL_PROVIDER=postmark` and `TRUST_PROXY` to the number of proxies in front; the API refuses to boot otherwise. Create the bucket yourself (only dev auto-creates it), keep it private, and give it a CORS rule allowing `POST` and `GET` from `APP_URL`: browsers upload straight to it with presigned POSTs.
- **Managed Postgres.** Migration 0002 marks `enum_eq`/`enum_ne` LEAKPROOF so status filters can use indexes under row-level security, which needs superuser. Where that isn't granted (RDS, Cloud SQL, Supabase) it logs a NOTICE and status filters scan the firm instead: fine at 300 doors, about 5× slower at 3,000. See AUDIT.md → Open decisions.
- **Logs.** JSON at `LOG_LEVEL` (default `info`). In development request lines are only logged at `debug`.
- **Health checks.** `/health` is liveness (the process is up). `/ready` is readiness (the database is reachable); point load balancers at `/ready`.
- **Worker failures.** A reminder that throws is logged, retired and skipped, so it can never block the reminders behind it. A failed send retries with backoff, and permanent provider errors (4xx) stop retrying. Messages to a teammate deactivated after a message was queued are skipped, and so is everything from a suspended firm.

## Not built yet (in PRD scope)

- **CSV import** of properties, units, owners, tenants and vendors (PRD US-01). This is the top priority next, because double entry is the biggest adoption risk.
- **Stripe billing** and the 15-work-order trial cap (US-27).
- **AI triage suggestions** (US-09). The `ai_suggestions` column exists.
- **Per-firm SMS registration** through Twilio's ISV APIs (prd §8.2). SMS sends only when `sms_registration_status = 'approved'`.
- **Inbound SMS** auto-reply, and **Postmark delivery webhooks** feeding delivery status into communication history.
- **Logo upload** to firm settings, and HTML email templates.
- **TOTP 2FA for firm users** (planned as a fast follow; superadmins already need an authenticator code).

## Known shortcuts

Each is marked in code with `shortcut:`.
- **Rate limits** are kept in memory per instance. Use a Redis store when running more than one API instance.
- **Emails** are plain text.
- **Document reminders** fire at 14:00 UTC rather than in the firm's own timezone.
- **Delivery** is at-least-once: a worker crash between send and mark can repeat a message.

## Running everything

From the repo root, `pnpm dev` starts Docker, migrations, this API, the worker and the web app, and seeds demo data. `pnpm check` runs lint, typecheck, these tests and more. See [../DEVELOPMENT.md](../DEVELOPMENT.md).
